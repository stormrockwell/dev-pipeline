## Secret and boundary cases

The secret defense and guardrail suites in `cli/test/secrets.test.ts`, `cli/test/hooks.test.ts` and `cli/test/guard.test.ts` pass: 3 files, 463 tests. They cover the planted secret cases that must block at commit (task 1.4) and the boundary cases for the shell tokenizer hook (task 1.5). The boundary cases run as unit tests for now, because the plugin they would run under as evals arrives in task 2.1.

## What the exit could not measure yet

- **Hook bypasses.** The pilot replayed history on read-only repos, so no developer worked under the hooks. The count moves to the Phase 2 exit, where a real feature ships on Media on Autopilot and a zone PR lands on the MCP server.
- **Peer approval enforcement.** Task 1.9 is done when a zone PR cannot merge without a peer approval. Both repos have one developer and run with `enforce-approvals: false`, so the test waits for the first team repo, as decision 13 records. The unit tests for the approval count pass.
- **Labels on dev-pipeline.** The risk gate computed `risk:critical` and `zone:guardrails` for the PR, then warned that `risk:critical` was not found, because dev-pipeline has no risk and zone labels yet. A failed label edit is a warning by design, since a fork's token is read only.
