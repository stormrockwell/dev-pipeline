# Spike 0.4: parallel PHP integration tests

Suite: media-on-autopilot integration, 242 tests. Hard timeout 300 s per run (perl process-group watchdog in `spikes/0.4-parallel-tests/run-concurrent.sh`).

| Arm | Solo time | Concurrent wall time per run | Result | Flaky? |
|---|---|---|---|---|
| Baseline, shared DB (`/tmp/moap-wp-tests`), 4 runs, not rerun | not run | run1 never finished, run2 96.6 s, run3 142.7 s, run4 47.9 s | run1 hung (would be timeout), run2 pass, run3 fail (1 error), run4 pass | Yes, collisions on the shared database |
| Solo reference, own `MOAP_DB_DIR` | 47.6 s | n/a | pass (242 tests, 500 assertions) | n/a |
| Arm 2, per-copy DB via `MOAP_DB_DIR`, round 1, 4 runs | 47.6 s | 48.0 s each | 4 of 4 pass | No |
| Arm 2, per-copy DB via `MOAP_DB_DIR`, round 2, 4 runs | 47.6 s | 47.8 s each | 4 of 4 pass | No |
| Arm 3, Playground CLI | not run | not run | blocked, exit 1 in 6 s during bootstrap, 4 at once not attempted | n/a |

Clone cost: a copy is 157 MB by `du -sh` but an APFS `cp -cR` clone of it added only about 6 MB of real disk (measured with `df`), because clones share blocks until written.

Recommendation: use Arm 2, one clone per run with `MOAP_DB_DIR` pointing inside it, because 4 concurrent runs matched solo wall time with no failures in 8 runs.

Blocker (Arm 3): the copies' `tests/wp-tests-config.php` and `tests/bootstrap-integration.php` hardcoded the DB directory, so the copies were patched to read `MOAP_DB_DIR` (`make-copy.sh` per-copy-db mode does the same). For Playground, `vendor/bin/phpunit` must be run as `wp-content/plugins/media-on-autopilot/vendor/bin/phpunit` because the working directory is `/wordpress`, and the bare path fails with "Could not open input file". With that fixed, `wp-phpunit/includes/bootstrap.php` line 261 runs `system( WP_PHP_BINARY . ' install.php' )` and Playground's `system()` returns 1 for every child, even `php -r "exit(0)"`, so the bootstrap calls `exit( 1 )` with no output. The fix is to set `WP_TESTS_SKIP_INSTALL=1` and install in-process from the plugin bootstrap, or ignore `$retval`, which needs a change to the test bootstrap and was not tried. Playground also warns that `@php-wasm` 3.1.62 wants node >= 24.18 (local is 24.17.0).
