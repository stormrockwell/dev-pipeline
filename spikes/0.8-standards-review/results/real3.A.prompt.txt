Commit message:
fix(cdn): reject hostnames already claimed by another tenant

attachHostname validated a hostname's format but never checked
whether it was already in use, and resolveTenant's lookup takes
.first() with no ORDER BY. A hostname collision (e.g. attaching one
tenant's own subdomain as another tenant's custom hostname) could
therefore resolve non-deterministically, bleeding one tenant's
immutable-cached images to another's visitors.

- attachHostname now checks for a row already using the hostname as
  subdomain or custom_hostname (excluding the tenant's own row) before
  calling addCustomHostname, returning 409 on conflict.
- The delivery worker's tenant lookup adds ORDER BY id, so a
  collision that does slip through resolves deterministically instead
  of varying per isolate/colo.
- Added partial unique indices (subdomain; custom_hostname WHERE != '')
  to schema.sql and a new migrations/0002-add-hostname-uniqueness.sql,
  as defense in depth at the database level.
